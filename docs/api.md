# API Contract

> The agreement between the frontend and the backend (README §8.1 "Contract first").
> Changes to this file need approval from both owners.
> Interactive version: run the server and open **http://localhost:8000/docs** (generated by FastAPI).

* Base URL (local): `http://localhost:8000`
* Format: JSON in, JSON out. Times are ISO-8601 UTC.
* Auth: `Authorization: Bearer <access_token>` from `/auth/login` or `/auth/register`.
* Errors always look like `{"detail": "Human-readable message"}`.
  Validation errors (`422`) use FastAPI's list format: `{"detail": [{"loc": […], "msg": "…"}]}`.

| Code | Meaning |
|---|---|
| 400 | Request understood but not allowed (e.g. bad ballot) |
| 401 | Not signed in / token expired |
| 403 | Signed in but not allowed (wrong role, not eligible, voting closed) |
| 404 | Not found (or not published yet) |
| 409 | Conflicts with current state (already voted, election already open, chain check failed) |
| 422 | Request body/params invalid |
| 423 | Account temporarily locked (too many wrong passwords) |
| 429 | Rate limit hit (login, receipt verify) |

Roles: `student`, `election_admin`, `system_admin`, `auditor`.

## Auth

### POST `/auth/register`
```json
{"student_id": "student01", "password": "at-least-8-chars", "full_name": "Amara Phiri"}
```
`201`:
```json
{
  "access_token": "Qm9…",
  "token_type": "bearer",
  "expires_at": "2026-10-16T10:00:00Z",
  "user": {"id": 4, "student_id": "student01", "full_name": "Amara Phiri", "role": "student"}
}
```
Errors: `409` student ID taken · `422` password shorter than 8 characters.
Self-registration always creates a **student**. To get an admin, register normally, then a
system admin promotes you with `PATCH /admin/users/{student_id}/role`. The very first system
admin is created from the command line: `python -m scripts.create_admin <student_id>`.

### POST `/auth/login`
`{"student_id": "...", "password": "..."}` → same shape as register (`200`).
Errors: `401` wrong ID or password (same message for both) · `423` locked for
`LOCKOUT_MINUTES` after `MAX_FAILED_LOGINS` failures · `429`.

### POST `/auth/logout` → `204`
### GET `/auth/me` → `UserResponse`

## Elections (public)

### GET `/elections` · GET `/elections/{id}`
```json
{
  "id": 2,
  "title": "Student Council 2026",
  "status": "open",
  "opens_at": "2026-10-16T07:50:00Z",
  "closes_at": "2026-10-16T09:52:00Z",
  "positions": ["President", "Treasurer"],
  "key_fingerprint": "9a1c…",
  "tallied": false,
  "results_published": false
}
```
`status` is computed from the server clock: `upcoming` → `open` → `closed`.

### GET `/elections/{id}/candidates`
```json
[{"id": 6, "election_id": 2, "full_name": "Amara Phiri", "position": "President", "manifesto": "…"}]
```

### GET `/elections/{id}/me` (signed in)
`{"election_id": 2, "eligible": true, "has_voted": false}`. Use this to show or hide the ballot.

### POST `/elections/{id}/vote` (student)
Request: exactly one candidate id for **every** position:
```json
{"choices": {"President": 6, "Treasurer": 8}}
```
`201`:
```json
{
  "receipt_code": "VC-AZ52-6H62-VTCE",
  "ballot_hash": "eb0287ef…",
  "status": "pending",
  "message": "Your vote has been recorded. It is waiting to be sealed into the next block."
}
```
> **Frontend:** this is the **only time** the receipt code is ever returned. Show it
> prominently with a copy button, and offer to save it in `localStorage`
> (My Receipts page) or download it. The server cannot recover it.

Errors:
| Status | `detail` |
|---|---|
| 400 | `Choose a candidate for: Treasurer` · `Unknown position(s): …` · `That candidate is not standing for President` |
| 403 | `Only students can vote` · `Voting has not opened yet` · `Voting is closed for this election` · `You are not on the voter list for this election` |
| 409 | `You have already voted in this election` |

### GET `/elections/{id}/results`
`404` until published. Then:
```json
{
  "election_id": 2,
  "title": "Student Council 2026",
  "published_at": "2026-10-16T10:01:00Z",
  "total_ballots": 4,
  "invalid_ballots": 0,
  "results_hash": "6f86…",
  "results_block": {"height": 3, "block_hash": "0007…", "merkle_root": "…"},
  "positions": [
    {
      "position": "President",
      "candidates": [
        {"candidate_id": 6, "full_name": "Amara Phiri", "votes": 2},
        {"candidate_id": 7, "full_name": "Brian Tembo", "votes": 2}
      ],
      "winner_ids": [6, 7],
      "tie": true
    }
  ],
  "results_document": "{\"ballots\":[…],\"counts\":{…},…}"
}
```
`results_document` is the exact JSON that was hashed into the final block.
`sha256(results_document) == results_hash`, so anyone can recount.

## Receipts

### POST `/receipts/verify`
`{"code": "VC-AZ52-6H62-VTCE"}`. Case, spaces, dots and dashes are ignored.

Not found (also returned for malformed codes):
```json
{"valid": false, "message": "We couldn't find that receipt. Check the code and try again."}
```
Found:
```json
{
  "valid": true,
  "message": "Receipt valid: your ballot is recorded on the chain and will be counted.",
  "election_id": 2,
  "election_title": "Student Council 2026",
  "ballot_hash": "eb0287ef…",
  "status": "confirmed",
  "block": {"height": 2, "block_hash": "000b82…", "merkle_root": "de43…", "timestamp": "…", "sealed_by": "node-3", "tx_count": 3},
  "merkle_proof": [["71c9…", "L"], ["a0f2…", "R"]],
  "counted": false
}
```
`status`: `pending` (waiting for a block) · `failed` (seal is being retried) · `confirmed`.
`counted` becomes `true` after the tally. The response never includes the candidate.

## Admin (election_admin)

### POST `/admin/elections`
`{"title": "…", "opens_at": "2026-11-01T07:00:00Z", "closes_at": "2026-11-01T15:00:00Z"}` → `201 ElectionOut`.
Also generates the election's encryption key (only its fingerprint is returned).

### PATCH `/admin/elections/{id}`
Any of `title`, `opens_at`, `closes_at`. `409` once the election has opened.

### Candidates
* POST `/admin/elections/{id}/candidates` `{"full_name", "position", "manifesto?"}` → `201 CandidateOut`
* PATCH `/admin/elections/{id}/candidates/{cid}` (any of those fields)
* DELETE `/admin/elections/{id}/candidates/{cid}` → `204`

All three return `409` once the election has opened (the setup is anchored in the genesis block).

### POST `/admin/elections/{id}/voters`
`{"student_ids": ["student01", "student02", "ghost"]}` →
```json
{"added": ["student01", "student02"], "already_eligible": [], "unknown": ["ghost"], "not_student": []}
```
Allowed until the election closes. Nobody is ever removed.

### GET `/admin/elections/{id}/turnout`
`{"election_id": 2, "eligible": 10, "voted": 4}`

### POST `/admin/elections/{id}/close`
`{"election_id": 2, "status": "closed", "blocks_sealed": 1}`. `409` if the election hasn't opened yet.

### POST `/admin/elections/{id}/tally`
Same shape as `/results` (but not yet public). `409` if still open, already tallied,
or chain verification failed (the reason is in `detail`).
This also runs automatically shortly after `closes_at`.

### POST `/admin/elections/{id}/publish` → `ElectionOut` with `results_published: true`.
`409` if not tallied.

### PATCH `/admin/users/{student_id}/role` (system_admin)
`{"role": "election_admin"}` (one of `student`, `election_admin`, `system_admin`, `auditor`) → `UserResponse`.
The change applies immediately, even to tokens the user already holds (the role is read on every request).
Errors: `401`/`403` not a system admin · `404` unknown student ID · `409` changing your own role · `422` unknown role.
Audited as `user_role_changed`.

### GET `/admin/audit-log?limit=100&offset=0`
```json
[{"id": 12, "actor_id": 1, "action": "election_closed", "detail": "{\"election_id\": 2}", "created_at": "…"}]
```
Actions: `user_registered`, `staff_login`, `account_locked`, `election_created`,
`election_updated`, `candidate_added`, `candidate_updated`, `candidate_removed`,
`voters_added`, `vote_cast` (no actor), `election_closed`, `election_tallied`,
`results_published`, `user_role_changed`, `staff_account_created`, `auto_tally_failed`, `chain_resync`, `chain_tamper_simulated`,
`chain_mismatch_at_startup`.

## Chain (public, read-only)

### GET `/chain/{id}/status`
```json
{"election_id": 2, "height": 2, "head_hash": "000b82…", "finalized": false,
 "pending_ballots": 0, "last_seal_error": null, "node_count": 3, "difficulty": 3, "block_size": 5}
```

### GET `/chain/{id}/blocks?offset=0&limit=50`
List of block headers (`transactions: null`). Fields as in [blockchain.md §4](blockchain.md#4-block-structure-and-hashing).

### GET `/chain/{id}/blocks/{height}`
One block including `transactions` (ballot hashes). `404` if no such block.

### GET `/chain/{id}/verify`
```json
{
  "election_id": 2,
  "healthy": false,
  "has_majority": true,
  "canonical_head": "000b82…",
  "canonical_length": 3,
  "nodes": [
    {"node_id": "node-1", "in_majority": true,  "valid": true,  "length": 3, "head_hash": "000b82…", "first_bad_height": null, "error": null},
    {"node_id": "node-2", "in_majority": false, "valid": false, "length": 3, "head_hash": "000b82…", "first_bad_height": 1, "error": "block 1: merkle_root does not match the transactions"}
  ],
  "database_copy": {"valid": true, "length": 3, "head_hash": "000b82…", "matches_majority": true}
}
```

### POST `/chain/{id}/resync` (system_admin)
`{"repaired": ["node-2"], "verify": {…}}`

### POST `/chain/{id}/simulate/tamper` (system_admin, dev only)
`{"node_id": "node-2", "height": 1, "mode": "edit" | "remine" | "drop"}` → `{"tampered": "…", "verify": {…}}`
